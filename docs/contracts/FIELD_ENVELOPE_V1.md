# قرارداد پاکت رمزشده و محتوای ورودی، نسخه ۱

این قرارداد بین گوشی (FD-07)، فضای ابری (FD-06) و برنامه‌ی دسکتاپ (FD-01، FD-05) است.

## پاکت (envelope)

هر ورودی یک فایل JSON است با این فیلدها:

| فیلد | نوع | معنی |
|---|---|---|
| `v` | عدد | نسخه‌ی پاکت، فعلاً `1` |
| `kdf` | رشته | `scrypt` |
| `n`, `r`, `p` | عدد | پارامترهای scrypt، فعلاً `32768`، `8`، `1` |
| `salt` | base64 | نمک ۱۶ بایتی، تصادفی برای هر پاکت |
| `nonce` | base64 | ۱۲ بایت، تصادفی برای هر پاکت |
| `ct` | base64 | متن رمزشده‌ی AES-256-GCM همراه برچسب احراز هویت |

- کلید ۳۲ بایتی از عبارت عبور و `salt` با scrypt ساخته می‌شود.
- داده‌ی احراز هویت (AAD) رشته‌ی ثابت `barkav-field-envelope-v1` است.
- تغییر هر بایت یا عبارت عبور اشتباه باعث خطا می‌شود.

## محتوای داخل پاکت (payload، JSON)

### رسید (`kind = "receipt"`)

| فیلد | الزامی | معنی |
|---|---|---|
| `kind` | بله | `receipt` |
| `id` | بله | شناسه‌ی یکتای رسید (از گوشی) |
| `caption` | بله (می‌تواند خالی باشد) | توضیح کاربر، جدا از هر متن OCR |
| `received_at` | بله | زمان ثبت روی گوشی، ISO 8601 |
| `image_b64` | بله | بایت‌های JPEG بدون EXIF، base64 |

### گزارش روزانه (`kind = "daily_report"`)

| فیلد | الزامی | معنی |
|---|---|---|
| `kind` | بله | `daily_report` |
| `id` | بله | شناسه‌ی یکتای گزارش |
| `report_date` | بله | تاریخ گزارش، `YYYY-MM-DD` (شمسی یا میلادی، با برچسب) |
| `body` | بله | متن گزارش، فارسی |

## قواعد

- فایل‌های Drive نام معنی‌دار ندارند. نام فایل فقط شناسه‌ی تصادفی است.
- برنامه‌ی دسکتاپ هر ورودی را یک بار می‌خواند (`remote_id` دیده‌شده ثبت می‌شود).
- محتوای ناشناخته‌ی `kind` نادیده گرفته و گزارش می‌شود، نه اینکه خطا شود.
- تغییر ناسازگار در این قرارداد یعنی `v: 2`.
