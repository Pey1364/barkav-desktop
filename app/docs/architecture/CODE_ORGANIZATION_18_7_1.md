# تقسیم‌بندی کد BARKAV 18.7.1

این ساختار از فایل «تقسیم بندی کد نویسی پیشنهاد کدکس» گرفته شده است.
انتقال در دو مرحله انجام می‌شود:

1. این مرحله: packageهای رسمی و facadeهای سازگار ایجاد شده‌اند؛ runtime همچنان از ماژول‌های ریشه استفاده می‌کند.
2. مراحل بعدی: هر ماژول پس از تست مستقل، به محل نهایی منتقل می‌شود و facade ریشه برای سازگاری باقی می‌ماند.

| بخش | مسیر رسمی | دامنه |
| --- | --- | --- |
| کیت طراحی | `barkav/design` | تم، فونت، RTL و اجزای ظاهری |
| هسته و پوسته | `barkav/core` | launcher، مرکز پروژه، runner، registry و تنظیمات |
| سرویس‌ها | `barkav/services` | SQLite، مالی، تراکنش، پروژه، بودجه، فروش، وام و پیوست |
| ماژول‌های کاربری | `barkav/features` | Dashboard، فروش و مطالبات، تقویم مالی و گزارش |
| گردش‌های مشترک | `barkav/workflows` | گردش تأیید و بازبینی تلگرام |
| یکپارچه‌سازی | `barkav/integrations` | Telegram و تاب‌آوری شبکه |
| خروجی | `barkav/outputs` | Excel، PDF، چاپ و Sheet Sync |

Facadeها عمداً فقط import مجدد انجام می‌دهند. بنابراین این مرحله هیچ تغییر دیتابیس، منطق مالی، رفتار UI یا قرارداد import موجودی ایجاد نمی‌کند.
