# BARKAV 18.7.1 — نقشهٔ مهاجرت مستقل

## هدف

18.7.1 یک بازنویسی مرحله‌ای از 18.7 است. قواعد مالی معتبر، SQLite به‌عنوان
منبع حقیقت و گردش تأیید انسانی حفظ می‌شوند؛ وابستگی اجرایی به فایل‌های دارای
نام نسخه‌ای قدیمی به‌تدریج حذف می‌شود.

نسخهٔ 18.7 مرجع فقط‌خواندنی و مسیر بازگشت است. داده‌های زنده، پیوست‌ها، لاگ‌ها
و secrets هرگز در این مهاجرت کپی یا Commit نمی‌شوند.

## لایه‌های هدف

1. **Core**: چرخهٔ عمر برنامه، پروژهٔ فعال، تنظیمات، ناوبری و لاگ.
2. **Design System**: توکن‌های تم، فونت، RTL، هندسه و اجزای مشترک.
3. **Data & Services**: پروژه، مالی، تراکنش، اسناد، قرارداد، خروجی و Audit.
4. **Feature Modules**: داشبورد، ثبت داده، تراکنش‌ها، فروش، پیمانکاران، گزارش‌ها، حساب مدیر و Telegram.
5. **Shared Workflows**: جدول، ویزارد، رکورد، جزئیات، نمایش سند و پیش‌نمایش خروجی.
6. **Integrations**: AI، API، همگام‌سازی آنلاین، وب و بسته‌های توزیع.

هیچ ماژول رابط کاربری نباید رنگ، فونت، فرمول مالی یا دسترسی مستقیم به SQLite را
به‌طور محلی تعریف کند.

## قراردادهای غیرقابل تغییر

- SQLite منبع حقیقت مالی است.
- دادهٔ Pending یا AI تا تأیید انسانی اثر مالی ندارد.
- حذف مالی audit-safe است.
- تاریخ‌های اجرا، ثبت، پرداخت، فاکتور و چک مفاهیم جدا هستند.
- هر تغییر فرمول باید با آزمون مقایسه‌ای برابر با 18.7 تأیید شود.

## ترتیب مهاجرت

1. ثبت ساختار مستقل و آزمون‌های سازگاری پایه.
2. انتقال Core و Design System با نام‌های بدون stage.
3. انتقال سرویس‌های پروژه، مالی، سند و خروجی همراه با آزمون Golden.
4. انتقال ماژول‌ها، هر بار فقط یک ماژول و یک Checkpoint.
5. حذف importهای نسخه‌ای فقط پس از سبزشدن آزمون همان ماژول.
6. اجرای آزمون کامل، بررسی دستی ویندوز و ساخت بستهٔ انتشار.

## معیار پایان

18.7.1 تنها زمانی آماده است که entry point آن فقط ماژول‌های 18.7.1 را import
کند، فرمول‌های مالی با 18.7 سازگار باشند، تست‌ها سبز باشند و پذیرش بصری ویندوز
به‌صورت واقعی انجام شده باشد.
